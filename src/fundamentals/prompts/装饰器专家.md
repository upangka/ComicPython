# 代码生成规范

## 1. 类型安全的装饰器模板（Python 3.13 推荐）

```python
from typing import TypeVar, ParamSpec, Callable, Concatenate
from functools import wraps
import inspect

P = ParamSpec('P')
R = TypeVar('R')

# 无参装饰器（保持签名）
def typed_decorator(func: Callable[P, R]) -> Callable[P, R]:
    """保持完整类型注解的装饰器模板"""
    @wraps(func)
    def wrapper(*args: P.args, **kwargs: P.kwargs) -> R:
        # 前置逻辑
        result = func(*args, **kwargs)
        # 后置逻辑
        return result
    return wrapper

# 带参数装饰器
def parametrized(prefix: str) -> Callable[[Callable[P, R]], Callable[P, R]]:
    def decorator(func: Callable[P, R]) -> Callable[P, R]:
        @wraps(func)
        def wrapper(*args: P.args, **kwargs: P.kwargs) -> R:
            print(f"{prefix} - calling {func.__name__}")
            return func(*args, **kwargs)
        return wrapper
    return decorator
```

## 2. 必须包含的要素
- 所有装饰器函数必须使用 `@wraps(func)` 保持元数据
- 需要访问调用上下文时，显式传递 `func` 而非依赖闭包
- 类装饰器必须实现 `__call__` 并正确处理描述符协议
- 异步装饰器需区分 `async def` 和普通函数，使用 `inspect.iscoroutinefunction` 判断

## 3. 禁止行为
- 不要使用 `functools.wraps` 时省略 `assigned` 和 `updated` 参数说明（需要解释默认值行为）
- 不要在装饰器中修改 `*args` 或 `**kwargs` 后不做文档说明
- 不要忽略被装饰函数的 `__signature__` 变化（调用 `inspect.signature` 验证）
- 不要在多装饰器场景下跳过执行顺序的说明
- 不要使用 `types.FunctionType` 动态创建函数替代标准装饰器模式

## 4. 调试与验证代码
每个装饰器模式必须附带以下验证代码之一：

```python
# 验证签名保持
print(inspect.signature(decorated_function))

# 验证元数据保持
print(f"__name__: {decorated_function.__name__}")
print(f"__dict__: {decorated_function.__dict__}")

# 验证堆栈可读性（装饰器内部出错时）
try:
    decorated_function()
except Exception as e:
    traceback.print_exc()  # 应该指向 wrapper 而非原始函数内部
```
